Chapter 01

Project overview

Problem statement

Alumni information is commonly fragmented across spreadsheets, social groups and outdated portals. Students and graduates cannot easily identify relevant mentors or referral contacts, while institutions lack verified engagement data and measurable outcomes.

Proposed solution

CMRunite converts static alumni records into an active professional network. It combines verified profiles with accountable mentorship, referrals, events, messaging, recommendations, graph discovery, privacy controls, institutional analytics and secure account management.

People

Verified alumni discovery, connections, messages and graph paths.

Outcomes

Mentorship milestones, referral pipeline, event participation and analytics.

Intelligence

Grounded assistant and explainable purpose-specific matching.

Objectives

  1. Maintain a verified, searchable and privacy-aware alumni network.
  2. Provide structured mentorship, referral and engagement workflows.
  3. Produce transparent recommendations backed by profile evidence.
  4. Protect credentials, sessions and personal-data choices.
  5. Give administrators measurable, database-derived engagement insights.
  6. Deliver a testable, documented and deployable final-year system.

Chapter 03

System architecture

React PWA
UI + offline shell
→
Express API
Auth + workflows
→
MongoDB
Source of truth
↔
Flask ML
Ranking

Socket.IO connects the React client and Express server for real-time delivery. The backend also communicates with the configured email provider and a process-local background queue.

Request trust boundary

  1. Browser sends an HTTP-only JWT cookie.
  2. Middleware verifies signature and expiration.
  3. The JWT jti must match an active server-side session.
  4. The user must still exist and be approved.
  5. Role, resource ownership, privacy and blocking are checked.
  6. Validated data reaches the model and database layers.

PWA behavior

The production build registers a service worker that caches the navigation shell and static assets. Private API responses are deliberately excluded. Offline users receive a dedicated fallback page; mutations remain online-only.

Chapter 06

Grounded assistant and graph intelligence

Assistant pipeline

Question
→
Intent + years + keywords
→
Privacy-aware profile scoring
→
Evidence + actions

The assistant does not fabricate people or depend on a paid AI key. It searches stored alumni attributes and shows which field matched. Recent conversation is retained in the UI.

Action safety: a mutation first returns a named confirmation preview. Only a second confirmed request can create a connection, and the backend rechecks self-action, duplicates, privacy and blocking.

Graph model

  • Solid edges represent accepted connections.
  • Dotted discovery edges represent a shared company or branch.
  • Breadth-first search produces the minimum-hop accepted path.
  • Neighbour-set intersection calculates mutual connections.
  • Users can search, filter, zoom, pan and inspect profiles.

Explainable recommendation engine

score =
  semantic_text × mode_text_weight +
  skill_jaccard × mode_skill_weight +
  domain_match × mode_domain_weight +
  branch_match × mode_branch_weight +
  location_match × mode_location_weight +
  experience_score × mode_experience_weight +
  bounded_feedback_adjustment

Signals

  • Word and character n-gram TF-IDF cosine similarity
  • Normalized skill aliases and Jaccard similarity
  • Domain, branch and location exact matches
  • Graduation-year experience compatibility
  • Explicit relevant, irrelevant, hidden and conversion feedback

Chapter 08

Security and privacy

RiskControl
Password exposurebcrypt hashes, default field exclusion and safe DTOs
Account enumerationGeneric password-recovery response
Reset token theftRandom token, SHA-256 hash at rest, 15-minute expiry and single use
Stolen sessionJWT jti, server-side session, revocation and logout-all
Privilege escalationRole and resource-ownership authorization
Personal-data leakageBackend visibility filters, redaction, blocking and data export
Brute forceRate limiting on login, OTP, registration and password endpoints
Unsafe inputZod/schema validation, body limits and bounded uploads
Unconfirmed automationAssistant preview/confirmation protocol

Secure password recovery

  1. User submits email and always receives the same response.
  2. Approved account gets a random raw token by email.
  3. Only a SHA-256 hash and expiry are stored.
  4. Reset validates hash/expiry and bcrypt-hashes the new password.
  5. Token fields are cleared and all sessions revoked.

Production recommendations

Use HTTPS, managed secrets, least-privilege MongoDB, private object storage, malware scanning, Redis/durable workers, centralized audit logs, backups, CSRF hardening, dependency scanning, load tests and an independent penetration test.

Node.js 20+, Python 3.11+, npm and MongoDB Community or Atlas.

1. MongoDB

brew tap mongodb/brew

cd Alumni-Connect/Backend
cp .env.sample .env
npm install
npm run dev

3. ML service

cd Alumni-Connect/ML-Service
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

4. Frontend

cd Alumni-Connect/Frontend
npm install
npm run dev

Chapter 13

Presentation and viva

Recommended ten-minute sequence

  1. Overview: open /demo and explain the problem.
  2. Architecture: explain four layers and trust boundary.
  3. Assistant: find a mentor and show confirmation.
  4. Graph: filter, pan and show a path.
  5. Workflows: show mentoring milestones and referral history.
  6. ML: explain signals, reasons and evaluation.
  7. Trust: show privacy and session revocation.
  8. Evidence: show analytics and test totals.

Fast viva answers

Why hybrid recommendations?

Text finds broad similarity; explicit skills/domain/location/experience provide controllable, explainable signals.

Why a separate ML service?

Python isolates ranking dependencies while Express remains the authentication and policy boundary.

How can JWT sessions be revoked?

The JWT has a random jti; middleware requires a matching active server-side session.

Is the assistant generative?

No. It is grounded deterministic retrieval, avoiding fabricated alumni facts and external AI dependency.

How is privacy enforced?

Backend filters/redaction and action rejection—not only frontend hiding.

What is the main limitation?

The labelled ML dataset is small and must grow before broad accuracy claims.

Chapter 14

Limitations and future scope

Current limitations

  • Four-case labelled recommendation benchmark.
  • Deterministic assistant instead of general language model.
  • Process-local cache and background queue.
  • Local uploads instead of managed object storage.
  • Email requires external credentials.
  • No institutional-scale load test or independent penetration test.
  • No automated account-deletion retention workflow.

Future scope

  • 50–100+ reviewed scenarios and statistical evaluation.
  • Sentence embeddings and consented learning-to-rank.
  • Redis, durable workers and centralized observability.
  • Object storage and malware scanning.
  • Calendar/video integrations and native push.
  • Multi-institution tenancy and governance-approved retention/deletion.
